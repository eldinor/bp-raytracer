# Ray Tracer

Ray tracing is a way of creating images by simulating how light travels through a scene. Instead of drawing only the visible surfaces with fast approximations, a ray tracer starts from the camera and sends virtual rays into the world. When a ray hits an object, the renderer calculates what happens next: the light can bounce, reflect, scatter, or be absorbed. By repeating this process many times, the program builds an image that looks much closer to real lighting.

This approach is popular because it naturally produces effects that are difficult to fake well with traditional real-time graphics. Reflections in metal, soft shadows, color bleeding between surfaces, and glowing objects illuminating nearby geometry all fall out of the same basic idea: follow the path of light. The result can feel more photographic, more believable, and more physically grounded.

The tradeoff is cost. Ray tracing asks the computer to do a large number of geometric tests and lighting calculations for every pixel. A single sample is rarely enough, so renderers usually trace many rays per pixel and average the result. That is why ray-traced images often begin noisy and become cleaner over time as more samples are accumulated.

Modern ray tracers usually rely on acceleration structures to stay practical. Instead of testing every ray against every object, they organize scene geometry into hierarchies so the renderer can skip large regions of space quickly. Without that kind of structure, even modest scenes would become too slow to render.

There are also different styles of ray tracing. A simple ray tracer might support direct lighting, shadows, reflections, and refractions. A path tracer goes further and uses random sampling to approximate global illumination, which means it can capture subtle indirect light bouncing around a scene. That is why path tracing is often associated with film rendering and high-quality offline graphics, although modern hardware is steadily bringing it closer to interactive use.

Today, ray tracing sits at the center of a major shift in computer graphics. Game engines use hybrid approaches that combine rasterization for speed with ray tracing for specific lighting effects. Offline renderers use path tracing to push realism even further. Across both worlds, the appeal is the same: one coherent lighting model can replace many handcrafted tricks.

In the long run, ray tracing matters not just because it looks better, but because it simplifies the logic of rendering. When the renderer is based on how light actually behaves, artists and developers spend less time fighting approximations and more time shaping the final image. That is why ray tracing has become one of the defining ideas of modern graphics.

## Current State Of This Ray Tracer

The current state of this project is already beyond a minimal demo. It is a static, on-demand path tracer running on the CPU in Web Workers, with Babylon.js used for scene preview, camera control, and GLB import. The final image is shown through a WebGL2 overlay, so the app feels interactive even though the actual ray tracing work is done separately from the real-time viewport.

Right now the renderer supports several scene primitive types. Native scene objects include spheres, boxes, and planes, and the default sample world also includes procedurally generated triangle meshes such as cylinders, tori, and wall quads. Imported GLB content is converted into triangle geometry and merged into the ray-traced scene, so the system can render both built-in shapes and external assets in one pipeline.

Material handling is also fairly advanced for a browser project of this size. The ray tracer works with a metallic-roughness style PBR material model, supports emissive materials, and can read base color, emissive, metallic-roughness, and normal textures from imported content. UV transforms, wrap modes, UV sets, and per-submesh material assignments are preserved during GLB import, which makes imported assets much closer to their preview appearance.

On the rendering side, the tracer already includes several practical quality features. It builds a triangle BVH with SAH-style splitting to accelerate ray intersections. It traces multiple bounces, mixes diffuse and GGX-style specular sampling, uses Russian roulette termination, and samples emissive geometry directly in addition to a directional light and sky contribution. That means the project is not just casting primary rays and shadows; it is already doing real light transport with importance-driven decisions.

The current image cleanup pipeline is another strong point. After accumulation, the renderer applies firefly suppression, A-Trous denoising guided by depth and normal buffers, isolated spike removal, and an optional soft cleanup blur. These controls are exposed in the UI, so the project already behaves like a small experimental renderer where you can tune stability versus sharpness rather than a fixed black-box demo.

Architecturally, the renderer is parallelized by splitting the target image into horizontal worker regions. Each worker streams partial tile updates while rendering, which allows the overlay to update before the full frame is complete. The user can choose worker count, resolution, sample count, bounce depth, material mapping behavior for GLB files, and multiple artifact-control parameters. Export is also implemented for pure ray-traced output, mixed preview output, and side-by-side comparison images.

At the same time, the project is still clearly in an early-to-mid experimental stage rather than a finished production renderer. It is static rather than fully progressive across time, currently runs on the CPU instead of GPU ray tracing hardware, and focuses on a compact set of materials and transport effects. There is no volumetrics, no subsurface scattering, no transmission pipeline for glass, and no large-scale scene management beyond the current serialized scene format. GPU support is planned for the nearest updates, which should make the renderer much faster and open the door to more ambitious real-time and near-real-time workflows. Even so, as it stands today, this ray tracer is already a serious sandbox for testing physically inspired lighting, imported assets, denoising ideas, and interactive render controls in the browser.
